# Brewery Settings Implementation Plan

> **For agentic workers:** Use the assigned independent domain and preserve other work. Steps use checkbox syntax.

**Goal:** Deliver all 32 settings with persistent behavior and rename Discover to Search.
**Architecture:** A shared Codable preference value drives SwiftUI via ObservableObject. Platform services own system integration; existing package/catalog services retain their responsibilities.
**Tech Stack:** SwiftUI, AppKit, Foundation, ServiceManagement, UserNotifications, XCTest; macOS 13+.
**Spec:** docs/superpowers/specs/2026-10-09-settings-design.md

## Global Constraints
- Preserve user modifications, no commits, pushes or Homebrew mutations during verification.
- No external dependencies. Test fixture mode must never send real notifications or use real commands.
- All exposed settings must work; report authorization failures and network failures.

## Review Focus
- Defaults, corrupt stored preferences and reset isolation: preference unit tests.
- Excluded tapped package identities and filters: package unit tests.
- Manual cadence, repeated notification events and changed paths: runtime policy tests.
- Cache clearing during in-flight requests: catalog tests.
- UI test fixture isolation and focus after switching settings: UI smoke tests.

### Task 1: Shared state and app integration (root)
- [x] Write isolated defaults/persistence/reset tests and implement AppPreferences.
- [x] Integrate theme, accent, language, startup page, remembered filters, window state and reduced motion.
- [x] Add Korean resources and rename user-visible Discover to Search.

### Task 2: Settings UI (settings agent)
- [x] Implement searchable categories and grouped settings forms using shared values.
- [x] Connect login, cache, Homebrew validation, diagnostics and release actions to real services.

### Task 3: Package and search behavior (packages agent)
- [x] Add meaningful filtering/exclusion tests then integrate package display preferences.
- [x] Integrate ranking period, catalog TTL/cache clearing and operation disclosure.

### Task 4: Runtime/system behavior (runtime agent)
- [x] Test cadence, release comparison, path override and retention policies.
- [x] Implement in-app schedules, permission-aware notifications, release checks, diagnostics, logs and executable resolution.

### Task 5: Integration and verification (root)
- [x] Build and run unit suite (164 tests, strict concurrency + warnings as errors). Run fixture UI smoke tests (2 passed) and inspect English/Korean settings screenshots.
- [x] Review all 32 requirements, resolve issues, document any platform limitations.

Verification limitation: 164 unit tests and 10 distinct UI scenarios are confirmed passing across runs; two existing uninstall-cancellation UI scenarios remain unverified due to XCTest menu/hit-point failures. See docs/qa/settings-2026-10-09.md.
