## Constraints

- Reuse attached managed worktree; preserve original changes and compare hashes before reintegration.
- No Homebrew mutations in the user's existing prefix or applications directory.
- Debug UI scenarios must never fall through to real Homebrew or network commands, including unknown commands and malformed scenario arguments.
- Release must not enable mock mode through launch arguments or environment.
- Native manual UI actions use cua_repl. Build UI tests without driving the computer through alternative UI APIs; distinguish compiled tests from executed tests.
- Do not claim unavailable OS/hardware QA from compilation or mocks. The user's final choice, “로컬 검증까지만 진행”, limits this delivery to local verification. Record unsupported-host, OS accessibility and hosted-CI execution as deferred acceptance Tasks rather than claiming they passed.
- No publish, push, PR, or CI dispatch without the corresponding user instruction. CI configuration is implemented locally.

## Review Focus

- Test launch paths accidentally mutating a real package or the normal cache/log files.
- Timing-sensitive tests passing without waiting for the expected state transition.
- CI building but silently skipping the UI target or fixtures.
- Instrumentation reporting body evaluation as a presented frame.
- Disposable Homebrew scripts accepting a prefix that overlaps a real installation or an existing user directory.
