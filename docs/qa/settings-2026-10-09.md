# Settings verification — 2026-10-09

Implemented the 32 setting candidates from the conversation using a shared persisted preference value and categorized Settings window. Discover is labeled Search; internal type names and accessibility identifiers remain compatible.

## Executed verification

- macOS Debug build and all 164 unit tests passed with `SWIFT_STRICT_CONCURRENCY=complete` and `SWIFT_TREAT_WARNINGS_AS_ERRORS=YES`.
- Two signed fixture UI tests passed: settings theme/search/Korean locale and sidebar Tab/Shift+Tab traversal.
- English dark Appearance and Korean General screenshots were visually inspected. Controls align to the right within grouped cards.
- Both localization files pass `plutil -lint`; `git diff --check` passes.
- The executable-change race regression was observed failing before the generation guard and passes afterward. It verifies a late outdated response cannot overwrite the new installation.
- Cache tests cover clearing memory/disk, preserving unrelated files, and rejecting in-flight responses after clearing.

The fixture uses transient preferences and fake Homebrew/catalog services. UI checks did not register a login item, request notification authorization, mutate real packages, or clear personal logs/cache. System-dependent login registration/notification delivery require normal macOS approval in an installed application and were not toggled during tests.

## Implementation decisions

- Automatic package checks run only while Brewery is open and use the serial Homebrew metadata refresh operation. Package upgrades remain explicit.
- Cleanup reminders are weekly reminders since the last observed cleanup, not automatic deletion or a background scan.
- Reset is guarded while operations are pending so it cannot switch the executable used by queued mutations.
- Window frame, filters, and appearance are restored from Brewery preferences; reset preserves Homebrew and package data.

## Broader UI regression result

The full 12-scenario suite was attempted. The latest evidence confirms 10 distinct scenarios passed across the full run and targeted retries, including settings/theme/Korean, Tab navigation, search/detail/back, offline data, filter persistence, queued-operation cancellation, selected upgrades, and missing-Homebrew recovery. The two existing uninstall-cancellation scenarios are not confirmed passing: XCTest encountered duplicate Touch Bar Cancel controls, then disappearing menu items / unavailable hit points during targeted retries. The latter attempts failed before verifying cancellation; no passing result is claimed for them. The test helpers now accept static text exposed as either AX label or value, use native keyboard dismissal, activate the target app, and use scrollbar dragging when wheel direction prevents scrolling. A stable desktop rerun is still required for those two scenarios.
